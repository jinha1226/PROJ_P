# 터치 컨트롤 커스터마이즈 — 설계

2026-07-11. 유저가 설정에서 터치 HUD를 직접 편집할 수 있게 한다: 액션 버튼
그리드의 슬롯별 명령 교체(+행 추가/삭제), 디패드 좌/우 위치와 크기.

## 결정 사항 (브레인스토밍 결과)

- **구조 내 커스터마이즈**: 하단 스트립 구조는 유지. 완전 자유 배치(드래그로
  화면 아무 곳에나)와 세로 위치 이동(상단/중간 배치)은 검토 후 제외 — 게임
  화면 가림과 구현·유지보수 비용 대비 실익 없음.
- **인플레이스 편집 모드**: 설정 화면 리스트 편집이 아니라, 실제 버튼
  스트립을 그대로 편집 대상으로 쓴다.
- **편집 범위**: 행동/기타 탭 그리드(슬롯 교체 + 행 1~4), 디패드 좌/우·크기
  3단. 핀 버튼(⇥/O), 디패드 9칸의 키, 헤더/푸터 버튼은 편집 불가.
- **저장**: localStorage(prefs) + 서버 RC 파일 주석 라인 백업. 시크릿 모드
  세션 간 유지가 목적.

## 1. 데이터 모델 (`prefs.ts`)

```ts
// Prefs에 추가
touchLayout: TouchLayout | null   // null = 기본 레이아웃

interface TouchLayout {
  v: 1
  dpad: { side: 'left' | 'right'; size: 'sm' | 'md' | 'lg' }
  tabs: { micro: Slot[][]; macro: Slot[][] }   // 행 배열, 각 행 4칸 고정
}
type Slot = { cmd: string } | { raw: string } | null
```

- `cmd`: 카탈로그 ID (예: `quaff`, `fire`). 라벨(한/영)·전송 키·모디파이어
  리라벨 매핑은 코드(카탈로그)가 소유 — 저장 JSON에 라벨을 넣지 않으므로
  번역·라벨 변경에 레이아웃이 깨지지 않는다.
- `raw`: 직접 입력한 키 1글자. 라벨은 그 글자 그대로. `send({msg:'input',
  text})`로 전송, 기존 Shift/Ctrl 규칙(`sendTabKey`)을 그대로 탄다.
- `null`: 빈 칸(스페이서 렌더).
- 검증: 파싱 실패, 알 수 없는 `cmd`, 행 수 0 또는 5 이상, 열 수 ≠ 4 →
  전체를 기본 레이아웃으로 폴백. 알 수 없는 `cmd` 하나만 있을 때는 그
  슬롯만 빈 칸 처리.
- 현재 `TAB_BUTTONS` 하드코딩이 기본 레이아웃의 원천. `getLayout()`이
  prefs → 기본 순으로 해석해 돌려준다.

## 2. 명령 카탈로그 (`src/game/input/touch-catalog.ts` 신규)

- 기존 양쪽 탭의 전 명령 + `ACTION_LABELS` 라벨을 합쳐 `{ id, labelPair,
  send(text|key), title }` 목록으로 추출. `TAB_BUTTONS`는 이 카탈로그 ID의
  기본 배열로 재정의된다 (단일 원천).
- 피커 그룹: 소모품·휴식 / 이동·계단 / 전투·시전 / 정보 화면 / 기타.
- 피커 말미에 특수 항목: **[직접 입력]** (1키 캡처 — 기존 kbd 오버레이를
  캡처 모드로 열어 다음 탭 1회를 가로챈다), **[빈 칸]** (슬롯 비우기).

## 3. 편집 모드 (인플레이스)

- 설정 오버레이에 "버튼 편집 / Edit buttons" 행 추가 → 설정이 닫히고
  스트립이 편집 모드로 전환.
- 편집 모드 UI: 콘텐츠 상단에 배너 — `슬롯을 탭해 명령 교체 · [＋행]
  [－행] [초기화] [완료]`.
- 편집 중 슬롯 탭 → 게임으로 키를 보내지 않고 카탈로그 피커 오버레이가
  뜬다. 선택 즉시 해당 슬롯 prefs 반영 + 리렌더 (편집 중 이탈해도 유실
  없음).
- 행동/기타 탭 전환은 편집 중에도 동작 — 양쪽 다 편집 가능. 디패드·헤더·
  푸터는 편집 모드에서 비활성(dim 처리).
- [－행]은 마지막 행 삭제, [＋행]은 빈 행 추가 (1~4행 제한, 한계에서
  버튼 dim). [초기화]는 한 번 더 탭해 확인(2-tap confirm) 후 `touchLayout
  = null`. [완료] → 편집 모드 종료 + `onRequestRebuild()`.

## 4. 디패드 위치·크기 (설정 오버레이)

- **위치** 행: `왼쪽 ↔ 오른쪽` 토글 → 루트에 `.dpad-right` 클래스, CSS
  `#touch-controls.dpad-right { flex-direction: row-reverse }`.
- **크기** 행: `작게/보통/크게` 3단 → `--tc-dpad`를 2.1 / 2.55 / 3.0rem으로
  루트 인라인 스타일에 설정. 기존 CSS 변수 체계 그대로.
- 두 토글 모두 기존 설정 토글과 같이 **click 전용** 리스너 (touchstart+click
  이중 발화 금지 — prefs 회귀 참조).

## 5. RC 백업/복원 (`rc-options.ts` 확장)

- 주석 라인 관리 함수 추가: `getRcComment/setRcComment` — `# pocketzot:layout
  <base64(json)>` 한 줄을 읽고/쓴다. 기존 옵션 파서는 주석을 건너뛰므로
  충돌 없음. DCSS도 주석은 무시하므로 unknown-option 경고 없음.
- 동기화 (게임 접속으로 RC 사용 가능해질 때 1회):
  - localStorage에 레이아웃 있음 → RC 주석과 다르면 RC에 기록 (백업).
  - localStorage 비어 있음(시크릿 새 세션) + RC에 있음 → prefs로 복원 후
    스트립 재구축.
  - 충돌 시 localStorage 우선 (방금 만진 쪽이 최신).

## 6. 테스트 (vitest, 기존 패턴)

- 레이아웃 직렬화/파싱·검증·폴백 (버전 불일치, 손상 JSON, 미지 cmd).
- 카탈로그 → 버튼 렌더 매핑 (라벨, 모디파이어 리라벨이 cmd 슬롯에도 적용).
- 편집 모드: 슬롯 탭이 게임에 키를 보내지 않음, 피커 선택이 prefs에 반영,
  행 추가/삭제 한계.
- RC 주석 라인 왕복(round-trip), 기존 옵션 라인 보존.
- 디패드 side 클래스·size 변수 적용.
